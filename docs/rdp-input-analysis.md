# RDP 入力の解析（実測: 2026-06-14）

## 1. 計測条件

2026-06-14 に iPad の「Windows App」から RDP でホストへ接続し、日本語を入力した。受け側には `ime-probe`（装飾のない Win32 ウィンドウ）を用い、届いたウィンドウメッセージを `probe.jsonl` に記録した。以下の所見はすべてこの記録による。

## 2. 所見

### 2.1 ホスト側の IME 変換は行われていない

記録を見ると、ホスト側の IME はまったく動いていない。届いたメッセージには次の特徴がある。

- すべての文字が `vk = 231`（`VK_PACKET`, 0xE7）の `WM_KEYDOWN` を伴う `WM_CHAR` として届く。
- `WM_IME_STARTCOMPOSITION`、`WM_IME_COMPOSITION`、`WM_IME_ENDCOMPOSITION` が1件もない。
- ローマ字の `WM_CHAR` も、`GCS_COMPSTR` / `GCS_RESULTSTR` の取得も発生しない。

`VK_PACKET` は `SendInput` に `KEYEVENTF_UNICODE` を指定したときに生成される仮想キーである。したがってこの経路では、iPad 側が日本語変換を終えたうえで、確定済みの Unicode をホストへ注入している。ホストの TSF と IMM32 はまったく通らない。

### 2.2 変換は読みの消去と再注入で構成される

確定のたびに、読みを注入し、Backspace で消してから変換結果を注入する順でイベントが届く。確定の瞬間はミリ秒間隔のバーストになる。`probe.jsonl` を時系列に並べ直した抜粋が次のものになる。

```
VK_PACKET  こ ん に ち は     読みが実文字として注入される
Backspace x5                  読みを消去する
VK_PACKET  今 日 は 仕 事     変換結果を注入する
Backspace x6
VK_PACKET  も し
...
```

Backspace の件数は記録のままである。抜粋のため、件数に対応する読みの注入行が含まれていない箇所がある。

iPad はホストアプリの中に候補ウィンドウを描画できない。そのため読みを確定文字として注入し、合成した Backspace で消去してから変換結果を注入する手順をとる。

### 2.3 二重化は新しいメモ帳でのみ発生する

手元で試した範囲では、二重化が起きたのは Windows 11 の新しいメモ帳（v11.2604.x、TSF / RichEdit ベース）だけだった。従来の Win32 エディットコントロールはこの消去と再入力の合成入力を正しく処理する。読みは残らず、変換結果がその位置を置き換える。

新しいメモ帳では読みの消去が終わる前に変換結果の注入が始まる。結果として消え残った読みの後ろに変換結果が入り、文字が二重になる。入力しようとした `変換が入るとおかしくなる。` は次のようになる。

```
へんかんがはいるとおか変換入るとおかしくなる。
```

## 3. 設計への影響

介入できる対象は注入される `VK_PACKET` と `Backspace` のストリームだけである。TSF テキストサービスや IMM32 を介して `GCS_RESULTSTR` と漏れたローマ字を正規化する当初の方針は、この経路に当てはまらない。正規化の対象となるホスト側の変換そのものが存在しないためである。

このストリームはグローバルな低レベルキーボードフック（`WH_KEYBOARD_LL`）で、イベントがメモ帳へ届く前に捕捉できる。パッケージ版メモ帳のプロセスへ DLL を注入する必要はない。

判別方法には注意がいる。この RDP 経路の入力では `LLKHF_INJECTED` フラグが立たず、通常のハードウェア入力として届く。そのため `VK_PACKET` 自体を合成入力のマーカーとして扱う。

## 4. 対策の実装

上記の方針を `kanafix` クレートとして実装した。設定した対象アプリが前面プロセスである間、`VK_PACKET` と `Backspace` のイベントを抑止し、ワーカースレッドから一定間隔（既定 6 ミリ秒）で再注入する。`VK_PACKET` は合成入力に限られるが、`Backspace` は発生源を判別できないため、物理キーボードの入力も同じ経路を通る。確定時のバーストを引き伸ばすことで、メモ帳の TSF が消去と再入力を取りこぼさなくなる。再注入したイベントには `dwExtraInfo` に印を付け、自分が送ったイベントを再び拾うフィードバックループを防いでいる。
